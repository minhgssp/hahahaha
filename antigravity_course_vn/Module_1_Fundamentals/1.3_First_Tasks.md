# 1.3 Các tác vụ đầu tiên

## Thông tin chung
- **Thời gian hoàn thành:** 15-20 phút
- **Yêu cầu:** Module 1.2 (Giao diện, @ mentions)
- **Bắt đầu:** Chạy lệnh `/start-1-3` trong Antigravity.

## Tổng quan

Module này hướng dẫn ba thao tác cốt lõi mà nhân viên văn phòng sử dụng hàng ngày: chỉnh sửa văn bản, soạn thảo tài liệu mới từ ghi chú, và tổng hợp thông tin từ nhiều nguồn.

**Điểm chính:** Kết hợp **@ mentions** (nhắc tên file) với các chỉ dẫn rõ ràng để AI giúp bạn làm việc nhanh hơn.

## Ba Thao tác Cốt lõi

### 1. Chỉnh sửa & Bổ sung (Append/Update)
**Mục đích:** Thêm tóm tắt vào biên bản cuộc họp, sửa lỗi chính tả, viết thêm nội dung vào báo cáo dở dang.

**Mẫu lệnh:**
```
Đọc @ten_file.md và thêm phần tóm tắt ở cuối file
```

**Quy trình:**
1. Antigravity đọc file.
2. Đề xuất nội dung mới.
3. Bạn xem xét và nhấn **Accept** (Chấp nhận).
4. File gốc được cập nhật.

**Ví dụ thực tế:** "Đọc `@ghi_chu_cuoc_hop.txt` và thêm một mục 'Việc cần làm' (Action Items) vào cuối file, liệt kê ai phải làm gì."

### 2. Soạn thảo Văn bản mới (Transform)
**Mục đích:** Biến ghi chú lộn xộn thành Email chuyên nghiệp, Tờ trình, hoặc Công văn.

**Mẫu lệnh:**
```
Đọc @file_nguon.md và tạo file mới tên file_moi.md định dạng theo [kieu_van_ban]
```

**Quy trình:**
1. Antigravity đọc file nháp/ghi chú của bạn.
2. Viết lại thành văn bản chỉn chu trong file mới.
3. File gốc giữ nguyên (để bạn đối chiếu).

**Ví dụ thực tế:** "Đọc `@y_tuong_tiec_tat_nien.txt` và tạo file mới tên `ke_hoach_tiec.md`, trình bày dưới dạng tờ trình gửi Sếp duyệt kinh phí."

### 3. Tổng hợp thông tin (Synthesize)
**Mục đích:** Đọc 10 báo cáo của nhân viên để làm báo cáo tổng hợp, tóm tắt ý kiến từ nhiều phiếu khảo sát.

**Mẫu lệnh:**
```
Phân tích tất cả file trong thư mục @ten_thu_muc và tạo file bao_cao_tong.md
```

**Quy trình:**
1. Antigravity đọc toàn bộ file trong thư mục đó.
2. Tìm các điểm chung, các con số quan trọng.
3. Viết ra một báo cáo tóm tắt duy nhất.

**Ví dụ thực tế:** "Đọc các file trong thư mục `@bao_cao_tuan` và tạo file `tong_hop_tuan.md` nêu rõ: Tổng doanh số, 3 vấn đề tồn đọng lớn nhất."

## Quy trình Làm việc với AI (Duyệt/Sửa)

Mỗi khi bạn ra lệnh, AI sẽ không tự ý sửa file ngay. Nó sẽ đi qua bước kiểm duyệt:
1. **Đề xuất:** AI hiện ra bản nháp (thường có màu xanh cho phần thêm mới).
2. **Xem xét:** Bạn đọc lướt qua.
3. **Quyết định:**
   - Ưng ý? Nhấn **Accept** (hoặc `Ctrl+Enter`).
   - Chưa ổn? Gõ thêm lệnh để sửa (ví dụ: "Viết ngắn gọn hơn", "Thêm kính gửi Alex").
   - Không thích? Nhấn **Reject** để hủy.

## Các tình huống mẫu tại TaskFlow

### Kịch bản 1: Xử lý Ghi chú họp
Bạn vừa họp xong với team Sales và ghi chú vội vàng trong `meeting_sales.txt`.
> "Đọc `@meeting_sales.txt` và thêm phần tóm tắt ngắn gọn các quyết định chính xuống cuối file."

### Kịch bản 2: Soạn Email báo cáo
Bạn cần gửi email cho Sếp (Alex) về tình hình nhân sự, dựa trên ghi chú của bạn (`notes_hr.txt`).
> "Đọc `@notes_hr.txt` và tạo file `email_gui_alex.md`, viết dưới dạng email báo cáo công việc, giọng văn trang trọng nhưng súc tích."

## Bí quyết ra lệnh (Best Practices)

**Hãy cụ thể:**
- ❌ **Mơ hồ:** "Viết cái này hay hơn."
- ✅ **Cụ thể:** "Đọc `@bao_cao.doc` và sửa lại văn phong cho chuyên nghiệp, kiểm tra lỗi chính tả."

**Luôn cung cấp ngữ cảnh:**
- ❌ **Thiếu:** "Làm báo cáo đi."
- ✅ **Đủ:** "Đọc `@so_lieu_thang_5.xlsx` và `@nhan_xet_khach_hang.txt` rồi tạo báo cáo tổng kết tháng."

**Lựa chọn đúng cách làm:**
- **Sửa file cũ:** Khi muốn cập nhật thông tin vào tài liệu đang có.
- **Tạo file mới:** Khi muốn chuyển đổi định dạng (Ghi chú -> Email/Tờ trình).
- **Phân tích:** Khi cần đọc nhiều file cùng lúc.

## Xử lý sự cố

**"AI tạo file xong tôi không thấy đâu"**
Kiểm tra lại cột bên trái (File Explorer). Đôi khi cần mở lại thư mục để thấy file mới.

**"Tôi lỡ tay Reject mất rồi"**
Không sao, hãy gõ lại lệnh (nhấn mũi tên lên để lấy lại lệnh cũ) và chạy lại.
